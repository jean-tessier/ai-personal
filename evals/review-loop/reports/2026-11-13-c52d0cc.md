# review-loop evals, 2026-11-13

This is iteration 2 of the skill-creator loop: 3 behaviour cases × 2 arms × 5 runs, with an Opus 5.5 orchestrator,
Claude Code 2.1.323 on macOS, driven by `run.sh` as headless `claude -p` sessions (ADR-0010, amendment of
2026-11-13). Every grader is scripted, and no LLM judge is used.

- **with_skill:** skill tree `c52d0cc` in the fixture repo, with the case prompt (`/review-loop feature/coupons against main`, …).
- **without_skill:** no skill. The prompt is the one-sentence outline the skill replaces, plus the same target.

## Results

| Case (graders per run) | with_skill | without_skill |
|---|---|---|
| `coupons-defaults` (11) | 55/55 (100%) | 50/55 (91%) |
| `model-overrides` (7) | 35/35 (100%) | 30/35 (86%) |
| `clean-branch` (4) | 19/20 (95%) | 15/20 (75%) |
| All grader results | 109/110 (99%) | 95/110 (86%) |
| Mean cost per run | $0.55 ($8.30 total) | $0.41 ($6.12 total) |

The skill-creator benchmark gives a mean per-run pass rate of 98% ± 6% for with_skill and 84% ± 12% for
without_skill. Wall time ranged from 65 to 393 s. The six case × arm pairs ran in parallel, so time depends on load
and isn't compared here.

## What separates the arms

- **Committing.** Every with_skill run committed its fixes and ended with a clean tree (15/15). Every without_skill
  run that changed code left the changes uncommitted (14/14; one clean-branch run changed nothing).
- **Model routing.** In `coupons-defaults`, with_skill used a Haiku fixer for the mechanical findings and a Sonnet
  fixer for the complex ones in 5/5 runs. Without the skill, 4 of 5 runs gave Haiku the complex source fixes (expiry, case, rounding) with exact code and used
  Sonnet only to write tests; `o-tiered-fixers` doesn't detect that. In
  `model-overrides`, both arms used only Sonnet, as asked.
- **Not discriminating.** The hidden behaviour test (`fixtures/coupons/hidden.test.mjs`) and the defect checks pass
  in all 30 runs. Opus fixes the seeded bugs either way, so the skill's value is the process around the fixes.
- **`clean-branch` isn't clean to Opus.** Both arms usually raise real edge cases: an invalid `now` applies an
  expired coupon, the lookup isn't limited to own properties, and the expiry cutoff is in UTC. The one with_skill
  failure (run 1, three reviews where two were allowed) came from a nit whose fix offered two edits. The orchestrator
  retagged it complex and skipped it instead of sending it back to the reviewer. Commit `27f293a` adds that rule;
  it was **not re-evaluated**.

## Iteration 1 (not committed)

Iteration 1 ran one run per case and arm ($2.81) on an earlier draft that grouped fixers by file and sent any group
with a complex finding to the complex model. With every finding in one file, Haiku never ran. Before iteration 2,
that draft was replaced by two waves per round (mechanical, then complex).

## Caveats

- There is one small fixture repo. Large PRs, CI, and the PR-number path (`gh pr view`, `gh pr checkout`) aren't
  exercised; every case targets a local branch.
- The baseline is the user's one-sentence outline, not an engineered prompt. A longer prompt that asks for commits
  would likely close most of the gap.
- Runs are small (5 per arm) and unpaired. The reviewer and fixer roles are classified by a heuristic on each
  subagent's description.
- Decisions are never asked interactively (headless runs), so they are carried to the report, and the
  AskUserQuestion path is untested.
- Cost: $14.42 for this iteration, about $17 including iteration 1.
